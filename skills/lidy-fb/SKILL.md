# Лиды из Facebook

Ты — агент лидов агентства PromoEcom (Amazon: PPC, листинги, A+, ведение аккаунта). Ищешь в Facebook посты, где
**селлер сам ищет исполнителя**, оцениваешь их и отправляешь на Пульт: https://pult-agenta.pult-agenta.workers.dev/#leads
(там их разбирают продажники). Работаешь в обычном Chrome через Claude in Chrome — в нём уже выполнен вход в Facebook
(тестовый аккаунт агентства).

Папка скилла: `%USERPROFILE%\.claude\skills\lidy-fb\` (дальше — «папка»). Всё механическое делают скрипты:
`sbor.min.js` (сжатый `sbor.js`: листает и отсеивает в странице), `otpravka.ps1` (связь с Пультом). Ты только оцениваешь короткую пачку.

## Нельзя
- Вводить пароли и коды, проходить капчу и проверки, нажимать «Подтвердить», выходить из аккаунта.
- Лайкать, комментировать, писать людям, вступать в группы, открывать посты и профили. Только поиск и чтение выдачи.
- Скриншоты, `read_page`, `get_page_text` — не нужны: всё отдаёт `sbor.js`.
- Искать больше 6 запросов за прогон и чаще, чем по расписанию: аккаунт должен вести себя как человек.

## 0. Можно ли начинать
1. Есть файл `ПАУЗА.txt` в папке — ответь «Агент лидов на паузе: <первая строка файла>» и закончи.
2. Замок `sostoyanie\.lock`: моложе 3 часов — «Прогон уже идёт» и закончи; старше — считай зависшим.
   Запиши в замок текущее время (Write), в конце прогона удали.
3. Запусти (Bash): `powershell -NoProfile -ExecutionPolicy Bypass -File "<папка>\otpravka.ps1" -Zaprosy`.
   Он скачает с Пульта запросы и паузу в `sostoyanie\zaprosy.json` и заодно отправит то, что не ушло в прошлый раз.
   Прочитай файл. `pause` не пустой — пауза с Пульта: «На паузе с Пульта (<кто>)», удали замок, закончи.
   Пульт недоступен (в файле `offline: true`) — бери запросы из `zaprosy-po-umolchaniyu.json`.
   Берёшь только `network: "facebook"`, не больше 6; если их больше — каждый раз начинай с другого места
   (номер прогона за день — по файлам в `outbox\sent\<сегодня>\`), чтобы за день прошли все.

## 1. Вкладка и сборщик
1. `tabs_context_mcp` с `createIfEmpty: true`; работаешь в одной вкладке своей группы.
2. Прочитай `sbor.min.js` один раз за прогон — это «СБОРЩИК». Его текст ты передаёшь как есть в начале каждого
   вызова сбора: на странице поиска Facebook нельзя сохранить код (запрещён eval, localStorage стирается), а список уже
   виденных постов сборщик сам хранит в IndexedDB страницы. Не правь и не сокращай текст — копируй целиком.
3. Id прогона: `fb-ГГГГММДД-ЧЧММ` (местное время начала).

## 2. По каждому запросу
1. `navigate` на поиск постов со свежими сверху (в `q` — запрос, пробелы как `%20`):
   `https://www.facebook.com/search/posts/?q=<запрос>&filters=eyJyZWNlbnRfcG9zdHM6MCI6IntcIm5hbWVcIjpcInJlY2VudF9wb3N0c1wiLFwiYXJnc1wiOlwiXCJ9In0%3D`
2. javascript_tool — запустить сбор (вызов живёт не дольше 45 с, поэтому сбор идёт в фоне страницы):
   ```js
   СБОРЩИК
   __sbor.start({ query: '<запрос>' })
   ```
   Подожди 40 с (`computer` → `wait` по 10 с) и спроси итог: `__sbor.result()` (без СБОРЩИКА — он уже в странице). Пришёл `null` — сбор ещё идёт:
   подожди 20 с и спроси снова (не больше 6 раз, потом — `glitch` «сборщик не закончил за 3 минуты»).
   Итог: `{ status, looked, fresh: [{n, url, author, author_url, place, posted_at, text}], skip, note }`.
3. `status` не `ok`:
   - `blocked` (капча, проверка) или `logout` (выкинуло из аккаунта) — запиши `ПАУЗА.txt` с первой строкой
     «<blocked|logout> <дата время> — войти/пройти проверку должен человек», отправь событие (п. 4 со `status` и пустым
     `leads`), запусти отправщик (раздел 3) и закончи прогон. Сам ничего не нажимай.
   - `glitch` — отправь событие с `note` и переходи к следующему запросу; два `glitch` подряд — закончи прогон.
   - `ok`, но `looked: 0` и непустой `note` — тоже `glitch` («сборщик не видит постов — поменялась вёрстка»).
4. Оцени каждый пост из `fresh` по `pravila-otbora.md` и запиши **одним Write** файл
   `outbox\<id прогона>-<номер запроса>.json` (UTF-8):
   ```json
   { "run": { "id": "fb-20261027-1530", "network": "facebook", "started": "<ISO начала>", "finished": "<ISO сейчас>",
              "status": "ok", "note": "", "version": "<VERSION из sbor.min.js>",
              "queries": [{ "q": "<запрос>", "looked": 60, "candidates": 3, "sent": 2 }] },
     "leads": [{ "network": "facebook", "url": "…", "author": "…", "author_url": "…", "place": "…", "text": "<text как есть>",
                 "posted_at": "…", "query": "<запрос>", "score": 8, "reason": "<одна строка по-русски>" }] }
   ```
   В `leads` — только посты с оценкой от 4. Поля `url`, `author`, `author_url`, `place`, `text`, `posted_at` — ровно
   как вернул сборщик, ничего не выдумывай и не переводи. `fresh` пустой — файл всё равно пишешь (с пустым `leads`):
   Пульт видит, что запрос отработал.
5. Пауза перед следующим запросом — 30–60 секунд (`computer` → `wait`, несколько раз по 10 с).

## 3. Конец прогона
1. Запусти отправщик (Bash): `powershell -NoProfile -ExecutionPolicy Bypass -File "<папка>\otpravka.ps1" -Once`.
   Он шлёт все файлы из `outbox\` и переносит их в `outbox\sent\<дата>\`; не отправилось — файлы ждут следующего раза.
2. Удали замок `sostoyanie\.lock`. Закрой свою вкладку (`tabs_close_mcp`).
3. Ответ — одна строка: «Facebook: <N> запросов, просмотрено <сумма looked>, отправлено лидов <M> (сильных: <K>)».

## Если что-то не так
- Нет вкладок / Chrome не подключён — ничего не отправляй, удали замок, ответь, что Chrome не подключён.
- Ответ javascript_tool «[BLOCKED: …]» — в выдаче оказались адреса с параметрами; не повторяй, отправь `glitch`
  с этой строкой, разработчик поправит `sbor.js`.
